# MasterTrip 3단계 — 로그인 + 동기화 설계

> 목표: 두 사람(나·배우자)이 같은 여행을 각자 폰에서 고치고, 인터넷이 될 때 서로 맞춰진다.
> 원칙: **폰이 먼저**(오프라인에서도 지금처럼 동작) · 앱 코드는 거의 그대로 · 동기화는 새 파일 하나(`sync.js`)로 더한다.

## 1. 서버 (Supabase, 프로젝트 `ogypfnqbtczhomdjrpvl`, 서울)
표 4개 + 함수 5개. 만드는 명령은 [`supabase/schema.sql`](../supabase/schema.sql).

| 표 | 한 줄 = | 하는 일 |
|---|---|---|
| `trips` | 여행 1개 | id(앱의 여행 id 그대로, 글자), 주인(`owner_id`), 지움 표시 |
| `trip_members` | 여행 × 사람 | 이 여행을 볼 수 있는 사람. 주인은 자동으로 들어감 |
| `trip_items` | 항목 1개 | 여행 정보·날짜 정보·일정·체크·지출·예약·연락처. `payload`에 앱 모양 그대로 |
| `trip_invites` | 초대 코드 1개 | 배우자 초대용 8자리 코드 (7일, 한 번만) |

- **잠금(RLS)**: 모든 표는 "내가 멤버인 여행만" 읽고 쓴다. 멤버 확인은 `is_trip_member()` 함수(표가 자기를 다시 확인하다 무한 반복 오류 나는 것을 피함).
- **멤버가 되는 길은 둘뿐**: 여행을 처음 올린 사람(주인), 주인이 만든 초대 코드를 넣은 사람. 직접 멤버 표에 쓰는 권한은 아무에게도 없다 (`trip-spain` 같은 id는 공개 저장소에 있어서, "자기를 넣기"를 허용하면 누구나 남의 여행에 들어올 수 있음).
- **시각·버전은 서버가 찍는다**: 저장될 때마다 트리거가 `updated_at = now()`, `version + 1`. 폰 시계는 쓰지 않는다.
- **지우기 = 지움 표시**(`is_deleted`): 진짜로 지우면 아직 못 맞춘 다른 폰이 다시 올려서 되살아남.
- 공개 키(publishable)는 앱에 들어가도 괜찮다. 비밀 키(secret/service_role)는 앱·저장소에 절대 넣지 않는다.
- 자동 노출을 껐으므로(Supabase 설정) 표·함수 권한은 SQL에서 로그인한 사람(`authenticated`)에게만 직접 준다.

### 함수
| 함수 | 하는 일 |
|---|---|
| `claim_trip(id)` | 여행 올리기 전에 부름. 없으면 만들고 내가 주인 → `'new'`, 이미 멤버 → `'member'`, 남의 여행 → `'taken'` |
| `push_items(trip, items)` | 항목 여러 개 보내기. 항목마다 "내가 마지막으로 본 버전(`base_version`)"과 서버 버전이 다르면 저장하지 않고 `conflict`를 돌려줌. `force`면 덮어씀 |
| `create_invite(trip)` | 초대 코드 만들기 (멤버만) |
| `join_trip(code)` | 코드로 여행에 들어가기 |

## 2. 앱 데이터 → 항목 나누기
여행 하나(`trip`)를 아래처럼 풀어서 `trip_items`에 한 줄씩. 받을 때는 거꾸로 묶는다.

| type | id | payload | 순서 |
|---|---|---|---|
| `meta` | `meta` | 여행 정보: title, emoji, places, region, people, currency, start, end, budget(환율·예산·환전 현금), preflight | – |
| `day` | `day:2027-04-07` | { date, city, note } | – |
| `item` | 일정 id | 일정 항목 그대로 + `date`(어느 날) | 그날 안의 순서 |
| `check` | 체크 id | 체크리스트 항목 | 목록 순서 |
| `expense` | 지출 id | 지출 | – |
| `booking` | 예약 id | 예약(바우처 목록 포함, 파일은 4단계) | – |
| `contact` | 연락처 id | 연락처 | 목록 순서 |

**폰에만 두는 것 (올리지 않음)**: 비상 서류(`vault`), 빠른 스크랩, 기록 탭 하루 사진(`day.photos`), 날씨·환율 저장본, 화면 설정, 결제 수단 기억.

## 3. 보내기·받기 (sync.js)
### 보낼 것 찾기 — "보낸 그대로" 저장본과 비교
- 폰에 `mastertrip-sync` 저장: 여행마다 `{ cursor(마지막으로 받은 서버 시각), rows: { 항목id: { v: 서버 버전, h: 보낸 내용 } } }`.
- 맞출 때 여행을 항목으로 풀어서, 내용이 `h`와 다른 것 = **보낼 것**. 저장본엔 있는데 지금 없는 것 = **지운 것**(지움 표시로 보냄).
- 그래서 앱의 수정 코드(일정 추가·지출 기록…)를 하나도 고치지 않아도 된다. 순서는 목록 위치(0,1,2…)를 그대로 쓴다.

### 언제
- 앱을 열 때, 앱으로 돌아올 때, 인터넷이 다시 연결될 때, 고친 뒤 몇 초 지나서(한꺼번에). 인터넷이 없으면 아무것도 안 하고 폰에서 그대로 동작.

### 순서
1. **받기**: `updated_at > cursor - 1분`(겹쳐 받아 빠뜨림 방지)인 항목을 받는다.
   - 내 폰에서 안 고친 항목 → 받은 것으로 바꾼다.
   - 둘 다 고친 항목 → **충돌**.
2. **보내기**: 보낼 것을 `push_items`로. 서버가 `conflict`라고 하면 → **충돌**.
3. **충돌**: "배우자가 먼저 고쳤어요" 창에 두 내용을 보여 주고 **내 것 / 배우자 것** 고르기. 내 것이면 `force`로 다시 보냄.

### 처음 로그인 (브릿지: 내 여행 올리기)
1. 올리기 전에 **백업 파일을 자동으로 하나 저장**.
2. 여행마다 `claim_trip` →
   - `new`/`member`: 모든 항목을 보낸다(서버에 이미 있으면 충돌 규칙대로).
   - `taken`(같은 id를 다른 사람이 먼저 올림, 예: 둘 다 시드 `trip-spain`을 따로 가진 경우): 묻기 — "배우자 초대 코드로 합치기" 또는 "내 것은 새 여행으로 따로 올리기(id 새로 만듦)".
3. 중간에 끊겨도 다시 하면 이어서 된다(이미 보낸 것은 버전이 같아서 건너뜀).

### 배우자 합류
- 주인: 여행 정보 창 → **함께 쓰기 → 초대 코드 만들기** → 카톡으로 코드 전달.
- 배우자: 로그인 → **초대 코드 넣기** → 그 여행이 내려와서 폰에 생김. 배우자 폰에 예전에 '여행 보내기'로 받은 같은 여행이 있으면 같은 id라 그대로 합쳐짐.

## 4. 로그인
- **이메일 + 6자리 코드**(비밀번호 없음). 메일 속 링크 방식은 설치한 앱이 아니라 크롬 창으로 열려 로그인이 엉뚱한 곳에 될 수 있어서 코드 입력 방식.
- Supabase 설정: Authentication → Email 사용, 메일 템플릿에 `{{ .Token }}`(코드)가 보이게, Site URL = `https://pmk8705.github.io/mastertrip/`.
- 로그인은 선택. 안 해도 지금처럼 혼자 폰에서 쓴다.

## 5. 라이브러리
- `supabase-js`를 `vendor/supabase/`에 넣는다(Leaflet처럼, 인터넷 없을 때도 앱이 깨지지 않게). 로그인한 사람만 불러온다.

## 6. 단계 (단계마다 배포)
1. **서버 준비** — SQL 실행, 로그인 설정 (사용자)
2. **로그인 + 내 여행 올리기(브릿지)** — 설정 탭 '함께 쓰기'
3. **둘이 맞추기** — 받기·보내기·충돌 창·초대 코드
4. **사진·바우처 파일** — Storage `trip-media/{여행id}/{파일id}` (멤버만)
5. (나중) 일정 알림 — Web Push

## 7. 알아 둘 점
- 무료 요금제: 1주일 동안 아무도 안 쓰면 프로젝트가 잠든다(대시보드에서 다시 켬). 잠들어도 앱은 폰 데이터로 계속 동작.
- 같은 항목을 둘이 동시에 고친 경우만 충돌 창이 뜬다. 다른 항목이면 자동으로 둘 다 산다.
